## Invited Talk: John E. Derrick (Authentrics.ai), _Diff, Trace, and Patch_  
11:45 am: **Paper Session 1A: Assurance and Security** (papers 6515, 2221, 2351) · Chair: Shibbir Ahmed

Traditional software is defined, measurable, and executable but the AI blackbox problem introduses an agentic AI problem in explainability, accuracy, etc. which ties into model safety. 

Instead of doing observation on the outside, it is important to do ongoing internal analysis and intervention on the analysis itself, instead of monitoring, stopping, and observation. This is done by leveraging accurate and purpose built fine tuned models. 

Authentrics software has key functions of monitoring and explanation and then what you do to fix it, which is intervention. When the first new checkpoint is available we can compare it to the previous version which allows for things like detecting poisoning attacks and modeling health analysis, which can be done without running any AI at all. Influence mapping helps with explainability by looking into the model to determine what checkpoint is responsible for a specific functinoality (when restricted material is introduced into a model). Once we determine a problem we need to intervene so we do things like only remove the effects of the training that needs to be removed, automatically, again without running an AI model. Lots of drift happens like, the desired outputs, how we are measuring the minima of errors, and the training that was done earlier can be redone. Using changes between checkooints allows for global stearing, which does require running the model. All of these are simple software solutions to monitor, explain, remove, and adjust... with AI coding skills that allow for this to be done automatically. 

Using mechanisms within the model to understand and control agents before they become end user problems. Guardrails all apply here like indications of quality and watching drift to make changes before it actually produces changes in behavior preventing it from effecting end users. 

Monitoring and maintanancce requires bserving things on the inside before the effect is observed, and if something appears to have drifted we can understand the source within the model efficiently. This can be pinpointed into a small specific part of the model, or we can just generally correct it. 

Discussion of an example of a drone which had some abnormal issue introduced at one checkpoint which was later identified, and this detection allowed for retraining on just that version with subsequent rollforward of the changes that were desired into future versions without needing to retraing all of the functionality that was learned between versions. Finding and fixing this produces 16% better performance in identification with 90% less compute resources on retraining that would have been required otherwise. 

Another example was a healthcare chatbot which was leaking personally identifiable information and it was possible to go back and edit this leaking out without needing to fully retrain the model. Big savings on accuracy without as big requirements on training compute resources.

### 2:00 pm - 2:20 pm Full paper TOP 3 PAPER A Metacognitive Framework for Test-Time Adaptation: Taxonomy and Research Challenges 
- Dario Loi, Gabriele Onorato, Antonella Coviello, Shahriar Rifat (Northeastern University); Nathaniel D. Bastian (DARPA); Francesco Restuccia (Northeastern University) 

Test time adaptation allows us to recover performance on failure cases based on differences in the training setting and the out of distribution sample if it is altered by some specific means. However useful adaptation, like ignoring coruptions, can be helpful when trained on corrupted in distribution data, but corrupted out of distribution data can make adaptation backfire into unintended behaviors. This leads to decreased accuracy throughout the adaptation steps. However we can try to for instance skip low confidence adaptation, which helps but has issues when it is not cognitively grounded. This raises the usefulness of metacognitive adaptation, being able to adapt on corrupted in distribution data and not try to adapt to corrupted information that is out of distribution. 

Test time adaptation methods concentrate on unconditional adaptation based on predictible signals like entropy, which uses this as a gate for how much it should be adapting to a specific instance. This assumes that the model is about right but can be adapted. This has lead to an explosion of methods for gating the adaptation signal based on things like memory banks of what is a usual in distibution sample or second order statistics beyond entropy. Past methods have focused on corruption specifically like which data nad when to adapt or how long the shifting has happened in non-stationary cases or which streams break it by stream conditioning. 

This method uses TTA with a meta level that measures the confidence in the model not just in terms of prediction confidence but a metacognitive measure of confidence by using the field of interpetability to understand why an instance should be adapted to or not. This includeds concepts of cue mapping. The metacognitive adaptation includes an object level, the NN, which has a meta level monitoring it and applying control over the object level. This can be done based on automatic cues, like entropy, or by deliberate cues which take some of hte information that the object level consideres as well a a model of the object level itself, combined with reasoning, that provides a better queue for adaptation. The adaptation template is done by gathering which knowledge we want to adapt, understand what is to be adapted, and figure out hoe it is to be regulated to prevent the objective from leading to catestrophic collapse. 

Concept extraction could be used to develop an interpretable TTA by taking a to be adapted item and splitting it into conceptual components, like an image of a car and a sky being split into factors within our concepts in a way that has a small residual. If an OOD sample is to be adapted to then the concept summation residual will be higher meaning the sample shouldn't be adapted to. The interpretability comes from the large residual and the constituent concepts that the sample is calculated to be composed of. 

The meta-level occurs when we compine the predictions of correctness, competence, and corruption to determine if there is a corruption, if the corrupted item is composed of instances that exist within sample, and the accuracy of prediction is relevant for not overfitting. Comparisons show that correctness is a good cue for automatic cues, wheras deliberate cues detect OOD inputs more reliably. 

Concept gating is used to reject harmful samples in a way that gives an interpretable explanation for refusal. Comparisons of contamination rate performance to see how much the performance was degrated showed that the higher the corruption rate the worse the automatic cues were at gating the bad samples, and the better the metacognitive method was at gating. By filtering using a metacognitive approach they were able to effectively gate the irrelevant cues and improve the adaptation without penalizing the accuracy.
